Each item also has feedUrl, siteUrl, language, itemId (stable hash), guid, updatedAt, summary (plain text, up to 1,000 characters), categories, imageUrl, enclosures (podcast audio, attachments) and fetchedAt. Dates are always ISO 8601 in UTC, whatever format the feed uses.

How to use

  1. Add feed URLs or websites to Feeds or websites, e.g. https://feeds.bbci.co.uk/news/technology/rss.xml or github.blog.
  2. Optional: Max items per feed (newest first), Only items from the last N days, Keywords.
  3. For monitoring, tick Only new items since the last run and schedule the tool (e.g. hourly). Give each schedule its own State key.
  4. Tick Include full item content to get the full text a feed publishes, not just the summary.
  5. Tick Only discover feeds to just find the feeds on a list of websites (feed URL, title, item count, latest item date).

A SUMMARY record lists each input with the feed found and how many items it returned. Sites with no feed, or whose robots.txt disallows access, are listed with the reason and not charged.

For AI agents

Call it via the Apify API or MCP server with {"feeds": ["github.blog", "theverge.com"], "maxAgeDays": 2, "maxItemsPerFeed": 20}. Every format comes back with the same fields, so an agent can read news from many sources without writing a parser for each one.

Data and responsibility

The tool reads only feeds that sites publish openly for readers. It follows each site's robots.txt and skips sites that restrict access instead of getting around it. Author names and other personal fields are not collected: you get the item's title, link, dates, summary, categories and media links. Content belongs to its publishers, so check their terms before republishing it in full.

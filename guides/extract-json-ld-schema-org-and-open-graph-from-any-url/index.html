How to extract JSON-LD, schema.org and Open Graph data from any list of URLs

Most websites already publish clean, machine-readable facts about each page for search engines: the product's price and availability, the recipe's cooking time, the FAQ's questions, the company's logo and address. That data sits in JSON-LD blocks, schema.org microdata and Open Graph tags. Reading it is much more reliable than scraping the visible page.

What you get

For each URL, the Structured Data Extractor returns one row with:

  • schemaTypes: every schema.org type on the page, e.g. Product, Offer, Recipe, FAQPage, BreadcrumbList, Organization
  • jsonLd: every JSON-LD block, with @graph lists flattened into separate items
  • microdata: schema.org items marked up with itemscope and itemprop
  • openGraph and twitterCard: all og:, article:, product: and twitter: tags
  • linkPreview: title, description, image, site name and URL, ready for a preview card
  • canonical, lang, favicon, feeds (RSS/Atom), hreflang and jsonLdParseErrors

Steps

  1. Open the tool on Apify and paste your URLs into URLs, one per line (up to 20,000 per run).
  2. Run it. Several sites are read in parallel, one request at a time per site.
  3. Export as JSON for the full nested data, or CSV/Excel for the overview columns.

Ideas

  • Schema markup audit: filter jsonLdCount = 0 to find pages with no structured data, and jsonLdParseErrors > 0 to find broken JSON-LD that search engines ignore.
  • Product feeds: read Product and Offer items for name, SKU, price, currency and availability from shops that publish them.
  • Link previews: use linkPreview to render cards in a chat app, newsletter or CMS.
  • AI agents: give an agent the page's facts as structured JSON instead of raw HTML.

Privacy

robots.txt is respected and sites that refuse automated requests are reported, never bypassed. Schema.org Person items and person fields such as author and review are removed, so the output holds business and page data only.
